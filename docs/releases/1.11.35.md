# TumoCompanion 1.11.35 (288)

- Recover a narrowly proven completed FW Packages installation when an obsolete
  activation journal remains but its old backup and staging copies are absent.
  The durable ledger, journal and fresh MD5s of every app must agree. This writes
  only the next state slot: no app reinstallation or deletion is performed.
- Preserve normal rollback whenever an old backup exists. Partial installations,
  modified/missing files, unknown observations, pending cleanup and transport
  failures cannot be mistaken for a completed transaction.
- Serialize catalog refresh, status verification, recovery, install, cleanup and
  catalog selection under the same updater transaction gate.
- Reject status adoption while a transaction is active and reject persisting a
  stale state generation after awaited device reads. Keep post-install status
  refreshes inside the owning transaction instead of starting a nested operation.
- Surface recovery read/verification failures without claiming rollback succeeded.

Refresh Feather and install **1.11.35 (288)**. If an unfinished-transaction error
is present, connect Flipper, keep the app open and use **Retry** once. Do not
delete `.tumoflip`, clear its journal manually or format the SD to hide an error.
Recovery remains conservative when the required proof is incomplete.

No firmware, API, FW Packages or package payload update is required. Existing
Community Apps cleanup protections remain unchanged. This patch does not claim
to identify the exact historical cause of every stale journal or to repair
unrelated BLE, SD hardware or OOM failures.

The IPA is ad-hoc packaged for re-signing with the user's certificate in Feather.
Publication, installation and physical-device acceptance are separate states.
