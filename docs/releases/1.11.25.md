# TumoCompanion 1.11.25

- Add a verified pre-update backup action in the Firmware Library. A backup is
  published only after the archive and its manifest pass integrity checks;
  read, size, device-MD5, and restore failures are surfaced instead of being
  reported as success.
- Show the redacted last-crash cause and app prefix in Device info when the
  connected Tumoflip firmware supports the Runtime App Bridge command.
  Earlier firmware continues to work and simply omits this card.
- Verify ESP32 Marauder release ZIP contents against the published package
  manifest before staging supported Module One v6.1 segments. The monitor
  reports a newly verified package without treating a changed ZIP under the
  same release tag as trusted. C5 remains a manual-flash path.

No breaking changes or automatic data migration. The crash card requires
Tumoflip Dev 009-015 or newer; backup and package validation work without it.

Hardware acceptance remains open: test backup and restore on a real Flipper,
fault/watchdog diagnostics with the matching firmware, Module One v6.1
staging/flash, and the manual C5 path before treating these features as
fully validated. Restore checks each file but does not provide an atomic
multi-file rollback after a mid-restore disconnect.
