# TumoCompanion 1.11.27

- Improve BLE keep-alive recovery when CoreBluetooth reports a failed connection:
  log the disconnect/connect error domain and code, then retry the selected
  Flipper while **Keep bridge alive in background** remains enabled.
- Retry the first failed connection immediately so CoreBluetooth has a pending
  request before iOS suspends the background-woken process. Repeated failures
  use bounded backoff (1, 2, 4, 8, 16, then 30 seconds) rather than a tight loop.
- User-initiated disconnects, a different selected peer, Bluetooth being off,
  and keep-alive being disabled do not trigger this retry path.

No firmware update, pairing reset, or user-data migration is required. iOS may
suspend or terminate an app in the background; state restoration and the
background central mode help service BLE events but do not guarantee continuous
execution. Force-quitting TumoCompanion still stops background BLE work.

Simulator unit tests and CI passed. Physical iPhone/Flipper background BLE
acceptance remains pending; verify foreground reconnect, backgrounding without
force-quitting, screen lock, out-of-range recovery, and the Flipper GAP reason
log before treating this as hardware-validated.
