# TumoCompanion 1.11.34 (287)

- Fix Community Apps cleanup routes reappearing because SD paths differed only in letter case or an old pending journal used an outdated catalog hash.
- Count only verified, actionable routes in **Clean Up N**. Keep unresolved paths under **Review** with their actual reason and a non-destructive **Recheck** action.
- Recognize apps whose binaries are current but remain at the old location. Offer an explicit **MOVE** installation at the new path before separate cleanup; never overwrite a destination that appears during that migration.
- Preserve interrupted cleanup recovery and unknown or modified files. A missing replacement remains an installation task, not permission to delete the original.
- Check cleanup again after catalog refresh, verification and installation. Serialize these operations and bind cleanup confirmation to the exact paths shown.
- Guard publication against replacing an existing release and verify uploaded IPA bytes before activating Feather metadata.

Refresh the Feather source and install **1.11.34 (287)**, then open Community
Apps and run **Check for updates**. If a **MOVE** row appears, install it first,
then confirm **Clean Up** separately. A remaining **Review** is not another
cleanup request: read the reason and use **Recheck** after resolving it.

No firmware or FW Packages update, pairing reset, automatic SD cleanup or
user-data migration is required. Signal recordings and user app data are not
cleanup targets. This patch does not establish a fix for unrelated BLE or OOM
reports.

The IPA is ad-hoc packaged for re-signing with the user's certificate in
Feather. Automated tests and Simulator screenshots do not replace installation
and physical-device acceptance.
