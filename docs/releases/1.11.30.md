# TumoCompanion 1.11.30 (283)

- Fix the BLE readiness regression introduced in1.11.28: Flipper serial TX uses
  READ|INDICATE, not NOTIFY. Accept both CoreBluetooth update-delivery mechanisms
  while still requiring confirmed subscriptions and actual RPC response evidence.
  This fixes the identified reason for a normal Flipper link staying in Connecting.
- Add a native regression that compiles the actual production discovery predicates
  against SDK property bits and the real firmware TX/flow contract. It no longer
  relies only on manually set readiness booleans.
- Show Preparing RPC when Bluetooth is connected but serial setup is incomplete;
  add diagnostics for characteristic properties and subscription state.
- Exercise the actual preparing placeholder and pixel renderer in UI tests, not
  only the decorative mock preview. Set the window height explicitly from the
  measured right column rather than relying on nested Button stretching. Width
  and normal two-column arrangement remain unchanged. Checks cover iPhone16Pro,
  both themes and different text sizes; physical rendering acceptance is separate.

No pairing reset, file migration, firmware/FW Packages/ESP32 update or automatic
device installation. Update the app through a refreshed Feather source and check
Settings > About shows1.11.30 (283) before comparing the connection/preview.

Known limitations: physical iPhone acceptance is separate from tests. The
previous public1.11.29 IPA was independently re-downloaded and confirmed as
version1.11.29/build282/source5c5547f with the published SHA256; that does not
by itself establish which build was installed on the reported phone. A separate
read-only lookup subsequently confirmed installed1.11.29/build282 on that iPhone.
